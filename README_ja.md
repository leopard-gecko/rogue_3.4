# Rogue 3.4 — macOS / Linux 移植版

本プロジェクトは、1981年のBerkeley版Rogue 3.4を復元したソースコードを、
現代のC11コンパイラと端末環境で動作するように移植したものです。
移植性やメモリ安全性に関する問題を修正しつつ、原典のゲームルールと
ASCII文字による画面表示をできるだけ維持しています。
**1981年の実行ファイルをバイト単位で再現したものではありません。**

[English README](README.md)

## 原典のソースコード

基準としたのは、Michael Toy、Kenneth Arnold、Glenn Wichmanによる
Rogue 3.4の復元ソースです。復元プロジェクトの元のREADMEによると、
修正した2.8BSDのツールチェーンでビルドすると、CSRG Archive CD-ROM
Disc 1の `2.8/usr/bin.v7/ucb/rogue` に収録された実行ファイルと
バイト単位で一致します（MD5: `88f791623b2a684d2555891c0f5b6735`）。

歴史的資料の `rogue.doc` は `2.8/usr/doc/rogue.doc`
（MD5: `e7113c0e9aedca6edf47f2127cfad4f7`）に対応し、
マニュアルページ `rogue.6` は4.1BSD由来です
（MD5: `f84eef587bc38bc0823f2cd029df030b`）。

これらの歴史的資料は、参照用として**変更せずに同梱**しています。
特に `rogue.6` に記載されている古いセーブ・スコアファイル名は
当時の環境のものであり、本移植版とは異なります。
現在の保存先は後述の説明を参照してください。

## ビルド方法

既定ではシステム標準のCコンパイラ（`cc`）を使用します。
展開したプロジェクトの `src/` ディレクトリで `make` を実行すると、
実行ファイル `rogue` が生成されます。
`./configure` や `CC=clang` の明示的な指定は不要です。

### macOS

AppleのCommand Line Toolsが未導入の場合は、次のコマンドでインストールします。

```sh
xcode-select --install
```

続いて、ビルド・実行します。

```sh
cd src
make clean
make
./rogue
```

macOSでは標準のコンパイラとcursesライブラリを使用するため、
Homebrewによる追加ライブラリの導入は不要です。

### Linux（Debian / Ubuntu）

コンパイラ、make、必要な開発用ライブラリをインストールします。

```sh
sudo apt update
sudo apt install build-essential libncurses-dev libcrypt-dev
```

展開したプロジェクトのディレクトリから、次のようにビルド・実行します。

```sh
cd src
make clean
make
./rogue
```

`libncurses-dev` はcursesのヘッダーとncursesのリンク用ライブラリを、
`libcrypt-dev` はゲーム内で使用する `crypt()` と `-lcrypt` に必要な
開発用ライブラリを提供します。

### Raspberry Pi OS

Raspberry Pi OSはDebian系のため、同じ開発用パッケージを利用します。

```sh
sudo apt update
sudo apt install build-essential libncurses-dev libcrypt-dev
```

ビルド・実行手順も同じです。

```sh
cd src
make clean
make
./rogue
```

**Raspberry Pi実機での動作は、32ビット版・64ビット版ともに未検証です。**
ここに示したのは想定するビルド手順であり、実機での動作を保証するものではありません。

### その他のLinuxディストリビューション

ディストリビューションのパッケージ管理ツールで、C11対応Cコンパイラ、
`make`、ncursesの開発用ヘッダー・ライブラリ、およびlibcryptの
開発用ライブラリを導入し、`src/` で `make` を実行してください。
MakefileはOSを判別し、macOSでは `-lcurses`、Linuxでは
`-lncurses -lcrypt` を使用します。必要なら `make CC=clang` や
`make CC=gcc` でコンパイラを指定できます。

**検証状況：** macOSでのネイティブビルドとゲームの動作は、移植版の
メンテナーが確認しています。Linuxでは、検証専用のcurses宣言ヘッダーと
システムのncurses実行ライブラリを使用したClang/GCCによるC11ビルド、
および端末の自動テストが通過しています。一方、`libncurses-dev` を用いた
通常のLinuxビルドとRaspberry Pi実機での動作は、別途確認していません。

ゲームの実行には、**80列×24行以上**の端末が必要です。
端末ウィンドウを大きくしても、内部のダンジョン画面は80×24文字のままです。
プレイ中に端末をそれより小さくすると、必要なサイズに戻るまでゲームが一時停止します。

## 操作方法・セーブ・スコア

| 操作 | コマンド |
| --- | --- |
| 新規ゲームを開始 | `./rogue` |
| ゲーム内ヘルプを表示 | `?` |
| 移動 | `h`、`j`、`k`、`l`（斜め移動：`y`、`u`、`b`、`n`） |
| 持ち物を表示 | `i` |
| オプションを開く | `o` |
| セーブして終了 | `S` を押し、`y` で確定 |
| 標準のセーブファイルから再開 | `./rogue -r` |
| セーブファイルを指定して再開 | `./rogue /path/to/savefile` |
| スコアを表示 | `./rogue -s` |
| 通常終了 | `Q` |
| 一時停止と再開 | `Ctrl-Z`、続いてシェルで `fg` |
| 対話シェルを開く | `!`、`exit` でゲームに戻る |

既定の保存先と形式は以下のとおりです。

- セーブファイル：`~/rogue.save`
- スコアファイル：`~/.rogue34.scr`
- セーブ形式：バージョン付きの `R34SAV01`（原典のプロセスメモリ保存形式とは互換性がありません）

セーブファイル名やHOMEディレクトリには、日本語などのUTF-8文字列や空白を使用でき、
原典の80バイトのバッファより長いパスにも対応しています。
ただし、本移植版の**セーブパス全体の上限は511バイト**（ディレクトリ名と
ファイル名を含む）です。

例えば、次のように `ROGUEOPTS` でHOME以下のセーブファイル名を指定できます。

```sh
ROGUEOPTS='file=~/保存.save' ./rogue
```

この場合、UTF-8のバイト列は別の文字へ変換されません。
パスが上限を超える場合は、途中で切り詰めずに起動時にエラーを表示します。
オプション画面は80列幅のため、長いパスを表示上だけ省略する場合がありますが、
実際に保存するファイル名は切り詰めません。
その他のゲーム内テキストは、原典と同じく基本的に1バイト文字による表示です。

正常に再開すると、使用したセーブファイルは削除されます。
破損などで読み込めなかったファイルは残します。
古いセーブ形式やスコア形式の自動変換は行いません。
セーブは `S` コマンドでのみ実行され、SIGHUP・SIGTERMによる終了時には
自動保存しません。信頼できない入手元のセーブファイルは読み込まないでください。

死亡時にはASCII文字の墓標を表示し、Returnキーが押されるまで保持します。
その後、スコアランキングを表示します。
また、原典どおり `w` コマンドで武器以外のアイテムも手に持てます。
端末上の表示やゲーム内メッセージは、この移植版でも英語のみです。

投擲中のアイテムは、見えるマスごとに約30ms表示します。
大文字の方向キーや数字指定による連続移動では、途中描画するマスごとに
約30ms待機します。通常の1マス移動と怪物の行動には遅延を追加していません。
`jump` が有効な場合、原典どおり連続移動中の途中描画を省略し、
追加の待機も行いません。

ゲーム開始時の挨拶は、ゲーム画面に切り替わる前に約1000ms表示します。
`S` によるセーブが成功した場合は、`File name: ...` を約1000ms表示してから
終了します。セーブ確認と再開時のメッセージは従来の入力処理を維持し、
通常のゲーム内メッセージや `--More--` には追加の遅延を設けていません。

## 配布内容と関連文書

- `src/`：ゲームのソースコード、`Makefile`、原典由来の案内書・マニュアル
- `PORTING.md`：移植の技術的な履歴、[原典とのゲームルール比較](PORTING.md#original-rules-audit)、移植性に関する注記
- `LICENSE`：再配布条件

ソース配布アーカイブに実行バイナリや検証専用のcursesヘッダーは含めていません。
`make clean` で生成されたオブジェクトファイルと `src/rogue` を削除できます。
原典の配布アーカイブに含まれていた未使用の編集用スクリプト `:ctfix` は、
ビルドに不要なため、本移植版の配布から除外しています。
